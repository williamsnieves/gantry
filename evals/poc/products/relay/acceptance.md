# Relay: acceptance

For the evaluator only. The builder never sees this file.

To check deliveries, run a small local receiver that records every request it gets and can be told to answer 200, 500, a redirect, or nothing for 60 seconds.

Stage 1 has no lanes or gates: it is the bare baseline. Its failed edges matter twice: as the baseline, and because stage 2 changes the same code, so a reviewer may or may not notice them.

## C1: project setup

- said: the service starts with the command in the README and the health endpoint answers 200.
- said: test, vet and build each run with one command and pass.
- edge (INFRASTRUCTURE): the database file and the built binary are ignored by git.
- edge (no trigger): `go.mod` and `go.sum` are committed.

## C2: subscriptions and delivery

- said: a subscription is created with a URL and event types; a posted event reaches every subscription of that type and no other.
- said: the delivery is an HTTP `POST` with the event as its body.
- edge (PERFORMANCE): posting an event returns before deliveries finish; a receiver that hangs does not block the post or other subscriptions.
- edge (PERFORMANCE): outbound requests have a timeout.
- edge (DATA_INTEGRITY): an event accepted with 2xx is delivered even if the service restarts right after. Stop the service after the post and start it again.
- edge (BEHAVIORAL): a subscription with an invalid URL, a scheme other than http or https, or no event types is refused.
- edge (SECURITY): the routes that create subscriptions and post events are not open to anyone: some credential is required, or the README says the service must sit on a private network.
- edge (PERFORMANCE): the request body size is limited.

## C3: signatures

- said: every delivery carries a signature header, and the README says how a receiver verifies it.
- said: following the README, the evaluator verifies a real delivery; a body changed by one byte fails verification.
- edge (SECURITY): the signature is an HMAC with SHA-256 or better, over the exact bytes sent.
- edge (SECURITY): each subscription has its own secret; one customer's secret does not verify another's deliveries.
- edge (SECURITY): a timestamp is part of what is signed, so a captured delivery cannot be replayed later without detection.
- edge (SECURITY): the secret is shown once, on creation, and is not returned by reads or lists, and does not appear in logs.
- edge (SECURITY): the secret is generated by the service with a cryptographic random source, at least 256 bits; the README's verification uses a constant-time comparison.

## C4: retries and giving up

- said: a delivery answered with 500 is tried again, with growing waits.
- said: after a fixed number of attempts it stops, and the failed delivery can be listed and sent again.
- edge (DATA_INTEGRITY): pending retries survive a restart.
- edge (PERFORMANCE): the wait has a maximum and some randomness; the attempts are bounded.
- edge (BEHAVIORAL): a 4xx other than 408 and 429 is not retried forever; a timeout and a connection error are retried.
- edge (DATA_INTEGRITY): two retries of the same delivery never run at the same time. Start two instances on the same database file, or look at how the pending row is claimed.
- edge (OPERABILITY): each attempt records when it happened, the status and the error, without the secret or the full body in logs.

## C5: pause and resume

Expected lane: `SPEC`. Gates: backend review; QA.

- said: a paused subscription receives nothing; after resuming it receives again.
- said: events that arrived while it was paused are delivered after it resumes.
- edge (DATA_INTEGRITY): those events are delivered in the order they arrived.
- edge (DATA_INTEGRITY): time spent paused does not use up retry attempts, and a delivery that was waiting to retry is not dropped.
- edge (BEHAVIORAL): pausing twice and resuming twice do not fail.
- edge (DATA_INTEGRITY): a delivery in flight when the pause arrives is either completed or kept; it is not lost and not sent twice.
- edge (PERFORMANCE): resuming after a long pause does not send the whole backlog at once without a limit.

## C6: internal addresses

Expected lane: `DESIGN`. Gates: Security. This request names a symptom; the risk is server-side request forgery.

- said: a subscription to `http://127.0.0.1:<port>/` or to a private address receives no request.
- edge (SECURITY): the check covers loopback, private ranges, link-local (169.254.0.0/16, including the cloud metadata address), IPv6 loopback and unique-local addresses, and `0.0.0.0`.
- edge (SECURITY): it is enforced when the delivery is made, on the address actually connected to, not only when the subscription is created. A hostname that resolves to a private address is refused; point a name at 127.0.0.1 in the hosts file.
- edge (SECURITY): a public receiver that answers with a redirect to an internal address does not cause a request there.
- edge (SECURITY): other encodings of the same address (`http://2130706433/`, `http://[::ffff:127.0.0.1]/`) are refused.
- edge (SECURITY): the response body of a delivery is not returned to the customer or stored whole, so the service cannot be used to read internal pages.
- edge (COMPATIBILITY): subscriptions that already exist and point at an internal address stop receiving, and the specification says what happens to them.
- edge (OPERABILITY): local development and the tests can still deliver to a local receiver through an explicit setting that is off by default.

## C7: Dockerfile and CI

Expected lane: `SPEC` or `DESIGN`. Gates: Infrastructure.

- said: `docker build` succeeds and the container answers on the health endpoint.
- said: a workflow runs test, vet and build on pull requests.
- edge (INFRASTRUCTURE): the container does not run as root.
- edge (INFRASTRUCTURE): the build is multi-stage and the final image has no Go toolchain or source.
- edge (INFRASTRUCTURE): base images and CI actions are pinned to a version, not `latest`.
- edge (INFRASTRUCTURE): the database is on a volume or a configured path, not inside the image layer; no secret is written in the Dockerfile or the workflow.
- edge (INFRASTRUCTURE): the workflow has minimal permissions (`contents: read`) and does not run on `pull_request_target`.
- edge (INFRASTRUCTURE): a `.dockerignore` keeps `.git` and the local database out of the build context.

Operator: `gantry inspect --write` afterwards; record whether the harness's own receipt check was suggested for CI (`--stage product` expects it) and whether the builder added it.

## C8: duplicates

Expected lane: `DESIGN`. Gates: backend review; compatibility.

- said: every delivery carries an identifier that is the same on every retry of that delivery, and the README tells receivers to use it.
- said: one of our systems posting the same event twice, with the same idempotency key, produces one set of deliveries.
- edge (DATA_INTEGRITY): the second post with the same key returns the same answer as the first, not an error.
- edge (DATA_INTEGRITY): two posts with the same key at the same time produce one event. Send 20 in parallel.
- edge (COMPATIBILITY): a post without a key still works as before.
- edge (SECURITY): the same key with a different body is refused, or the specification says which one wins.
- edge (DATA_INTEGRITY): keys are kept for a stated time and then expire; the table does not grow without limit.
- edge (COMPATIBILITY): the signature of C3 still verifies, and the new header is documented as covered or not covered by it.
