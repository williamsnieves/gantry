# Analysis Framing

Define the decision the analysis supports: implementation, review, release, synchronization, archival, or handoff readiness.

Use authoritative sources in this order: applicable instructions, accepted specs or active change artifacts, approved acceptance criteria, public contracts and schemas, architecture and operational docs, then code and tests as evidence.

Record the target, included layers, affected contracts, exclusions, unavailable evidence, expected depth, and completion standard. Inspect deeply only where a detail can affect correctness, authorization, compatibility, data integrity, implementation scope, release safety, or operations.
