# Handoff Readiness

The exploration handoff exists to support change creation without replaying the full investigation.

## Ready

Use when:

- the problem and outcome are clear;
- current behavior is understood sufficiently;
- affected capabilities are identified;
- a change action is selected;
- material product and architecture decisions are resolved;
- scope and exclusions are explicit.

## Conditionally Ready

Use when change creation can begin but named decisions must remain explicit in the artifacts.

## Not Ready

Use when:

- the problem is not supported by evidence;
- change ownership is unresolved;
- a blocking decision changes the intended behavior or architecture;
- affected capabilities cannot be identified;
- scope is unstable.

## Creation Handoff

Provide inputs for:

- change rationale;
- proposed scope;
- expected behavioral deltas;
- design constraints;
- task workstreams;
- validation expectations;
- open decisions.

Do not create proposal, specs, design, tasks, or a change directory.
