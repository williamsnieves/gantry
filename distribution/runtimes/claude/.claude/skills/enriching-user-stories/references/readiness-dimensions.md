# Readiness Dimensions

Assess only dimensions relevant to the request.

## Product Intent

- Problem or opportunity.
- Intended user or actor.
- Desired outcome and value.
- In-scope and out-of-scope behavior.

## Functional Behavior

- Primary flow.
- Inputs, outputs, and state changes.
- Business rules.
- Error, empty, loading, and recovery behavior where relevant.
- Compatibility expectations.

## Interfaces and Data

- Affected UI, API, events, schemas, fields, or storage.
- Validation and ownership.
- Migration or backward-compatibility impact.

## Architecture and Delivery

- Likely components or boundaries affected, when discoverable.
- Dependencies and integrations.
- Rollout, feature flag, migration, or deployment considerations.
- Documentation and operational updates.

Do not prescribe exact files or architecture unless confirmed by project evidence.

## Quality Attributes

Consider when relevant:

- security and privacy;
- accessibility;
- performance;
- reliability and resilience;
- observability;
- localization;
- browser, device, or platform support.

## Verification

- Observable acceptance criteria.
- Required test levels.
- Validation or monitoring expectations.
- Definition of done beyond code completion.
