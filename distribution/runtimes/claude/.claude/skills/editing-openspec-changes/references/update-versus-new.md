# Update Versus New Change

## Update the Active Change

Update in place when the same underlying outcome remains valid and the revision is refinement.

Examples:

- better technical approach;
- clarified requirement;
- narrowed scope;
- corrected assumption;
- newly discovered task;
- revised sequencing;
- additional scenario supporting the same intent.

## Create a New Change

Recommend a new change when:

- the problem itself changed;
- the intended outcome changed fundamentally;
- scope expanded into materially different work;
- the new work can complete independently;
- preserving the original change provides clearer history;
- the active change can finish without the new request.

## Split Strategy

When scope is narrowed:

1. update the current change to the deliverable that will complete now;
2. preserve its coherent acceptance behavior;
3. create a later change for deferred independent scope.

## Evidence

Record:

- original intent;
- proposed revision;
- relationship between them;
- independence test;
- decision and rationale.

Do not keep expanding a change merely to avoid creating another one.
