# Documentation Standards

Follow project rules first.

- Describe approved current behavior, not preferred design.
- Match the intended audience and existing document depth.
- Preserve hierarchy, terminology, navigation, code-block style, and link conventions.
- State prerequisites, defaults, compatibility, failure behavior, and version boundaries.
- Prefer canonical links over duplicated volatile details.
- Use current names, paths, interfaces, and safe non-production examples.
- For deprecation, state replacement and migration path; include timelines only when approved.
