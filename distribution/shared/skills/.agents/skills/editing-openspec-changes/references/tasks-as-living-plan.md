# Tasks as a Living Plan

Tasks are an editable checklist, not a frozen contract.

## Allowed Revisions

- add newly discovered required work;
- remove work proven unnecessary;
- reorder dependencies;
- split tasks that are too broad;
- combine meaningless microtasks;
- reopen a completed task when its result no longer satisfies the revised artifacts.

## Truthful Status

A checked task must represent work that remains valid after the revision.

Do not:

- preserve a checkmark for obsolete or insufficient work;
- mark newly described work complete without evidence;
- erase completed history without explaining replacement or invalidation;
- hide scope growth in vague task wording.

## Mandatory Coverage

Tasks should continue to cover relevant:

- implementation;
- tests;
- validation;
- documentation;
- migration;
- security;
- performance;
- observability;
- rollout and operations.

## Resumption

After editing, identify the first actionable incomplete or reopened task.
