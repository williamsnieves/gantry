# Option Analysis

Create multiple options only when meaningful alternatives exist.

For each option, assess:

- behavioral fit;
- compatibility with current architecture;
- scope;
- dependencies;
- migration or rollout;
- security and privacy;
- performance;
- reliability;
- operational complexity;
- testability;
- reversibility;
- known unknowns.

## Recommendation

A recommendation should explain:

- why it best fits current evidence;
- what trade-offs are accepted;
- what would invalidate it;
- whether approval is still required.

Do not manufacture alternatives merely to fill a template.
Do not present a proposed option as an approved decision.
