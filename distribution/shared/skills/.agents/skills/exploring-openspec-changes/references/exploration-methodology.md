# Exploration Methodology

## Principle

Bring the problem, not a pre-committed solution. Read the project before recommending architecture.

## Investigation Loop

```text
question → targeted discovery → evidence → updated understanding → next question
```

Stop retrieving context when additional information is unlikely to change scope, options, risk, or recommendation.

## Framing

Capture:

- initial problem;
- desired outcome;
- known actors;
- current symptoms;
- existing acceptance criteria;
- constraints;
- assumptions;
- unresolved questions.

## Current-State Discovery

Trace only what is necessary:

- entry points;
- affected behavior;
- data and interfaces;
- dependencies;
- tests;
- operational behavior;
- existing documentation.

## Problem Refinement

The investigation may confirm, narrow, expand, or invalidate the initial hypothesis.

Record:

- confirmed facts;
- corrected assumptions;
- inferred behavior with confidence;
- unresolved uncertainty.

## Exploration Outcomes

A valid exploration may conclude:

- create a new change;
- continue or edit an active change;
- split the work into multiple changes;
- gather more evidence;
- make a product or architecture decision first;
- do not proceed.

Not creating a change can be a successful outcome.
